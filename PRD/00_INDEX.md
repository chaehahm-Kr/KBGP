# 지금까지 확정된 8가지 답변 (이 문서 전체의 전제)

| 질문 | 답변 |
|---|---|
| MVP(Phase 1) 범위 | 신청 접수 + 심사까지. 샘플·견적·PO·배송은 이후 단계 |
| 거래 구조 | Letusto가 브랜드로부터 직접 매입해 미국에 재판매 (Merchant of Record). PO와 결제 흐름이 모두 Letusto를 거침 |
| 내부 인원 | 소수 인원(1~3명)이 심사·영업·운영을 겸임 |
| 예상 규모 | Phase 1 연간 30~100건 |
| 신청 단위 | 회사 하나에 여러 브랜드, 브랜드당 여러 제품 |
| 심사 단위 | 신청서 전체 상태와 제품별 심사 상태가 서로 독립적 |
| 현재 운영 방식 | 아직 실제 신청을 받아본 적 없음 — 마이그레이션할 기존 데이터 없이 처음부터 시작 |
| 결제 범위 | 이 시스템은 문서·상태 관리만 담당. 실제 결제(은행송금·L/C 등)는 시스템 밖에서 이루어짐 |

이 8가지가 이후 모든 문서의 설계 근거입니다. 답변이 바뀌면 여러 문서가 연쇄적으로 바뀌니, 나중에 뒤집을 경우 저에게 다시 알려주세요.

# 마케팅 사이트와의 관계 (중요한 맥락)

이전에 함께 기획한 K Select Network 마케팅 사이트(현재 프론트엔드로 배포됨, `www.kselectnetwork.com`)는 이 운영 플랫폼의 **입구**입니다.

```
마케팅 사이트 (기존)                    →   운영 플랫폼 (이번 기획)
자가진단 6문항                         →   Company 회원가입 자격의 사전 필터
"파트너 신청하기" CTA                   →   Company 회원가입 + Application 제출
정식 신청폼 (/apply/form)              →   이 문서의 "참가 신청서 제출" 기능으로 흡수
미팅 예약 (/apply/meeting)             →   이 문서의 "상담 예약" 기능(Phase 2)으로 흡수
```

즉 마케팅 사이트의 신청 퍼널 뒷단이 이번에 기획하는 시스템의 앞단(Company 온보딩)과 정확히 맞물립니다. 개발 시 마케팅 사이트의 "파트너 신청" 버튼이 이 플랫폼의 로그인/회원가입 페이지로 연결되는 구조를 권장합니다.

**충돌 발견 — 확인 필요:** 마케팅 사이트 기획 당시 미팅 예약은 **Microsoft Bookings 연동**으로 확정했는데, 이번 요청서에는 **Google Calendar 또는 Zoom 연동**이 후보로 적혀 있습니다. 둘 다 만들 필요는 없으니 `04_Phase별범위.md`의 Phase 2에서 하나만 선택해야 합니다. 이미 회사에서 Microsoft 365를 쓰고 계신 것으로 알고 있어 이 문서 전체는 잠정적으로 **Microsoft Bookings**를 기준으로 작성했습니다. 다르면 알려주세요.

# 아직 확인되지 않은 것 — 1차 기획서에서 제가 임의로 가정한 부분

아래는 답을 몰라서 미룬 게 아니라, **PM 판단으로 합리적 기본값을 정하고 문서에 반영한 것**입니다. 각 항목 옆에 제가 어떤 근거로 정했는지 적었습니다. 다르게 하고 싶으시면 해당 문서에서 바로 수정 가능합니다.

| 항목 | 제 판단 | 근거 |
|---|---|---|
| 미팅 예약 도구 | Microsoft Bookings | 이미 결정된 사항 + 기존 M365 사용 |
| 샘플·견적·PO를 Phase 2로, 생산·배송 추적을 Phase 3으로 분리 | 그렇게 함 | "심사까지만 MVP"라고 답하셨으므로, 남은 기능 중 "거래 성사 전 단계"(샘플·견적·계약·PO)와 "거래 성사 후 이행 단계"(생산·검사·배송)를 자연스러운 분기점으로 나눴습니다 |
| 전자서명 도구 (계약서) | Phase 2에서는 업로드+상태추적만, 전자서명 연동은 Phase 3 이후 | 계약서 자체가 요청 목록에 "관리"로만 적혀 있어 서명 자동화까지는 요구되지 않았다고 판단 |
| 결제 게이트웨이(카드결제 등) | 범위에서 완전히 제외, 상태값만 관리 | 답변에서 명시적으로 "문서·상태관리만"이라고 하셨음 |
| 통화 단위 | 견적·PO는 USD 기준, 원화 참고 표시는 선택사항 | 미국向 판매 사업 특성상 |
| Retailer(미국 리테일러) 포털 시작 시점 | Phase 3 | 원 요청에 "향후"로 명시됨 |
| 다국어(한/영) | 관리자 포털은 한국어 우선, 외부 파트너 포털은 한/영 병행 | 회사 담당자가 한국인일 가능성이 높지만, 향후 미국 리테일러도 같은 포털 계열을 쓸 수 있어 구조는 다국어 대응 가능하게 설계 |

이 표의 항목들은 언제든 뒤집을 수 있는 가정이니, 읽으시다가 아니다 싶은 부분은 편하게 짚어주세요.
