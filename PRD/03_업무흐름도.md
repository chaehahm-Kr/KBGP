문서: 03. 전체 업무 흐름도
---

이 시스템은 하나의 거대한 흐름이 아니라, 서로 이어지는 4개의 흐름으로 나뉩니다. 화살표 `→`는 순서를, `⇢`는 조건부 분기를 뜻합니다.

# 흐름 1 — 온보딩 & 심사 (Phase 1)

```
[게스트]
  마케팅 사이트에서 "파트너 신청" 클릭
        │
        ▼
[회사 회원가입]
  회사 정보 입력(회사명, 사업자등록번호, 국가, 담당자 연락처) → Company Admin 계정 생성
        │
        ▼
[회사 프로필 완성]
  회사 소개, 생산 캐파, 인증 현황 등록
        │
        ▼
[브랜드 등록] → [제품 등록] (제품별 이미지·인증서 업로드)
        │
        ▼
[신청서 작성]
  하나의 신청서 안에 제품 1개 이상 선택해서 담기
        │
        ▼
[신청서 제출] ─────────────────────────────► 신청 상태: 제출됨
        │
        ▼
[Letusto 담당자 배정] (Reviewer 또는 Super Admin이 자동/수동 배정)
        │
        ▼
[서류 심사 시작] ───────────────────────────► 신청 상태: 심사중
        │
        ├─⇢ 자료 부족 → [추가 자료 요청] → 회사에 알림 → 회사가 보완 제출 → 심사 재개
        │
        ▼
[제품별 개별 심사] (신청서 상태와 별도로 제품마다 승인/보류/반려)
        │
        ▼
신청서 전체 결과 판단
        │
        ├─⇢ 제품 전부 반려 → 신청 상태: 반려
        ├─⇢ 일부 제품만 승인 → 신청 상태: 부분승인 (승인된 제품만 다음 단계로)
        ├─⇢ "지금은 시기상조" 판단 → 신청 상태: 보류(재신청 안내 포함)
        └─⇢ 승인 → 신청 상태: 승인 ───────► 흐름 2로 이동
```

**Phase 1은 여기서 끝납니다.** "승인"이라는 결과가 나오는 지점까지가 1차 목표입니다.

# 흐름 2 — 파트너십 성사 (Phase 2)

```
신청 상태: 승인 (흐름 1에서 이어짐)
        │
        ▼
[상담 미팅 예약] (Microsoft Bookings 연동, 필요 시)
        │
        ▼
[샘플 요청] → [샘플 발송] → [샘플 수령 확인] → [샘플 평가]
        │                                          │
        │                          ┌───────────────┴───────────────┐
        │                          ▼                                ▼
        │                    평가 긍정적                        평가 보류/부정적
        │                          │                                │
        │                          ▼                          [신청 상태: 보류]로 되돌림
        ▼                          │                          (흐름 1의 "정직한 진단"과 동일 정신)
[견적 요청] ◄─────────────────────┘
        │
        ▼
[견적 작성 및 발송] → [협상/수정] → [회사 측 견적 승인]
        │
        ▼
[계약서 작성 및 공유] → [양측 서명 확인] ─────► 계약 체결
        │
        ▼
[PO 작성] (Letusto → 공급사/브랜드사, 매입 계약이므로 Letusto가 발행 주체)
        │
        ▼
[PO 내부 승인] → [PDF 발행 및 이메일 발송] → [공급사 PO 확인/승인]
        │
        └─⇢ 공급사가 조건에 이의 제기 → [변경 요청] → 재협의 → 재발행
        │
        ▼
PO 확정 ────────────────────────────────► 흐름 3으로 이동
```

# 흐름 3 — 이행: 생산부터 미국 입고까지 (Phase 3)

```
PO 확정 (흐름 2에서 이어짐)
        │
        ▼
[생산 대기] → [생산중] → [생산 완료]
        │
        ▼
[품질 검사]
        │
        ├─⇢ 불합격 → [재작업/재생산 요청] → 검사 재실시
        │
        ▼
검사 통과
        │
        ▼
[출고 준비] → [선적/출고] (Invoice, Packing List, BOL 문서 생성)
        │
        ▼
[국제 운송중] → [미국 통관중]
        │
        ▼
[미국 창고/매장 입고 완료] ──────────────► 브랜드사·Letusto 양쪽에 알림
        │
        ▼
[결제 상태 업데이트] (시스템은 상태 기록만, 실제 송금은 외부에서 처리)
        │
        ▼
주문 완료 ─────────────────────────────► 흐름 4(Phase 3+)로 연결 가능
```

# 흐름 4 — 미국 리테일러 (Phase 3, 원 요청서의 "향후")

```
[미국 Beauty Supply 매장 회원가입/로그인]
        │
        ▼
[제품 카탈로그 열람] (승인·입고 완료된 제품만 노출)
        │
        ├─⇢ [디스플레이(진열) 신청]
        ├─⇢ [제품 주문] → 흐름 3과 유사한 주문 상태 추적
        ├─⇢ [재주문] (이전 주문 기반 간편 재주문)
        └─⇢ [교환 요청]
        │
        ▼
[Letusto와 메시지] / [인보이스 확인]
```

이 흐름은 이번 문서에서 상세 설계하지 않습니다. Phase 3 착수 시점에 별도로 상세 기획하는 것을 권장합니다.

# 흐름 간 연결 요약

```
흐름 1 (신청·심사)  →  흐름 2 (샘플·견적·계약·PO)  →  흐름 3 (생산·배송·입고)  →  흐름 4 (리테일러, 향후)
   Phase 1               Phase 2                        Phase 3                    Phase 3+
```

한 회사(Company)는 여러 신청서를 낼 수 있고, 신청서 하나가 승인되면 그 신청서 안의 승인된 제품들만 흐름 2로 넘어갑니다. 즉 흐름 2 이후의 모든 상태값은 "신청서" 단위가 아니라 **"신청서 안에서 승인된 제품" 단위**로 움직인다는 점이 중요합니다. (상세는 `07_데이터모델.md`의 `ApplicationProduct` 참고)
