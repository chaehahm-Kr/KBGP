# Part 1 — 이메일 및 알림 규칙

## 기본 원칙

1. **상태가 바뀌는 모든 순간에는 관련자에게 알린다.** 사람이 매번 전화·이메일로 안내하지 않아도 되게 하는 것이 이 시스템의 핵심 가치 중 하나입니다.
2. **알림은 이메일을 기본 채널로 한다.** 인앱 알림(로그인해야 보이는 알림)은 보조 수단입니다. 담당자가 로그인하지 않아도 중요한 소식은 이메일로 도착해야 합니다.
3. **내부 직원 알림과 외부 회사 알림은 문구 톤이 다르다.** 외부용은 정중하고 브랜드 톤(마케팅 사이트의 "절제된 확신" 톤과 일치)을 유지하고, 내부용은 실무적이고 짧게 작성합니다.

## Phase 1 알림 이벤트 목록

| 이벤트 | 받는 사람 | 채널 | 내용 요지 |
|---|---|---|---|
| 회원가입 완료 | 신규 가입자 | 이메일 | 이메일 인증 링크 |
| 신청서 제출 완료 | 제출한 회사 담당자 | 이메일 | 신청번호, 제출 내용 요약 |
| 신규 신청서 접수 | 내부 Reviewer 전체(또는 담당 규칙에 따라) | 이메일 + 대시보드 강조 | 회사명, 제품 수, 확인 링크 |
| 담당자 배정됨 | 배정된 내부 직원 | 이메일 + 인앱 | 신청번호, 배정 사유 |
| 담당자 배정 해제됨 | 이전 담당자 | 인앱 | 참고용 |
| 추가 자료 요청 발송 | 회사 담당자 | 이메일 | 요청 내용, 회신 마감 안내 |
| 추가 자료 회신 도착 | 담당 내부 직원 | 이메일 + 인앱 | 회신 내용 요약, 확인 링크 |
| 심사 결과 확정(승인/부분승인/보류/반려) | 회사 담당자(Admin + 관련 Staff) | 이메일 | 결과, 사유(있는 경우), 다음 단계 안내 |
| 소속 사용자 초대 | 초대받은 사람 | 이메일 | 가입 링크 |
| 초대 만료 임박 | 초대한 Company Admin | 인앱 | 재초대 유도 |
| 추가 자료 회신 기한 임박/초과 | 회사 담당자(임박), 내부 담당자(초과) | 이메일 | 리마인드 |

## 알림 문구 원칙 (예시)

- 외부용 심사 승인 예시: *"[회사명]님, [신청번호] 신청이 승인되었습니다. 다음 단계인 상담 예약 절차를 곧 안내드리겠습니다."* — 사실만 전달, 과장 없음(마케팅 사이트 톤 원칙과 동일)
- 외부용 보류 예시: *"[신청번호]에 포함된 일부 제품은 지금 시점에는 진행이 어렵다는 판단입니다. 상세 사유와 재신청 가능 시점을 함께 안내드립니다."* — "거절"이 아니라 "아직 아니다"라는 톤 유지
- 내부용 예시: *"[신청번호] 신규 접수 — [회사명], 제품 3건. 확인: [링크]"*

## Phase 2·3에서 추가되는 알림 (개요만)

샘플 발송/수령, 견적 발송/승인/만료 임박, 계약 서명 완료, PO 발행/확정/변경요청, 생산·검사·출고 단계 전환, 지연 발생, 미국 입고 완료, (Phase 3) 리테일러 주문 접수. 상세 문구와 조건은 각 Phase 착수 시 확정합니다.

## 알림 설계에서 주의할 점 (개발 시 유의사항)

- **알림 중복 발송 방지**: 같은 이벤트로 여러 알림 규칙이 겹칠 수 있는 지점(예: 심사 결과 확정이 동시에 "신청 상태 변경"과 "제품 상태 변경" 두 이벤트를 발생시킬 수 있음)에서는 회사 담당자에게 이메일이 2통 가지 않도록 이벤트를 하나로 묶어 처리합니다.
- **알림 끄기 기능**: 회사 담당자가 계정 설정에서 알림 항목별로 on/off 할 수 있게 합니다. 단 "심사 결과 확정"처럼 반드시 받아야 하는 알림은 끌 수 없게 예외 처리합니다.

# Part 2 — 파일 및 문서 관리 규칙

## 다루는 파일 종류

| 파일 종류 | 업로드 주체 | 관련 화면/기능 | Phase |
|---|---|---|---|
| 제품 이미지 | 회사 | 제품 등록 | 1 |
| 인증서(성분·상표권·FDA 등) | 회사 | 제품 등록 | 1 |
| 추가 자료 요청 회신 첨부파일 | 회사 | 추가 자료 요청 | 1 |
| 대화 첨부파일 | 회사, 내부 직원 | 메시지 | 2 |
| 계약서 PDF | 내부 직원(업로드), 회사(열람) | 계약 관리 | 2 |
| PO PDF | 시스템 자동 생성 | PO 관리 | 2 |
| Invoice / Packing List / BOL | 내부 직원 | 문서 관리 | 3 |

## 공통 규칙

1. **허용 형식**: 이미지(JPG, PNG, WEBP), 문서(PDF), 스프레드시트(XLSX, CSV — 성분표 등). 실행 파일(EXE 등) 및 압축파일 내 실행파일은 원천 차단합니다.
2. **최대 용량**: 파일당 기본 10MB. 계약서·PO 등 문서류는 20MB까지 허용을 검토합니다(스캔본 등 큰 파일 고려).
3. **저장 위치와 접근 제어**: 모든 업로드 파일은 직접 URL로 접근할 수 없고, 반드시 로그인 세션을 거쳐 권한을 확인한 뒤에만 열람 가능하게 합니다. (`10_보안과권한요구사항.md`와 연결)
4. **버전 관리**: 같은 문서(예: 성분표)를 다시 업로드하면 기존 파일을 덮어쓰지 않고 새 버전으로 추가합니다. 이전 버전도 계속 열람 가능해야 심사 시점의 근거가 보존됩니다.
5. **삭제 정책**: 회사·직원이 파일을 "삭제"해도 실제로는 물리 삭제하지 않고 숨김 처리합니다(법적 분쟁 대비, 심사 이력 보존). 완전 삭제는 Super Admin만, 별도 사유 기록과 함께 가능합니다.
6. **보관 기간**: 계약서·PO·Invoice 등 거래 관련 문서는 최소 5년 보관을 권장합니다(일반적인 상거래 문서 보관 관행 — 정확한 기간은 회사의 법무·회계 자문을 받아 확정하는 것을 권장드립니다. 이 부분은 제가 임의로 정한 값이니 꼭 확인해 주세요).
7. **바이러스/악성코드 검사**: 업로드 파일은 저장 전에 자동 검사를 거치는 것을 권장합니다(특히 인증서·성분표 파일은 제3자로부터 받은 파일을 그대로 올리는 경우가 많아 위험이 있습니다).

## 문서 생성(시스템이 자동으로 만드는 문서, Phase 2·3)

- **PO PDF**: PurchaseOrder 확정 시 시스템이 정해진 양식으로 자동 생성 → 이메일 첨부 발송
- **계약서**: Phase 1~2에서는 자동 생성이 아니라 업로드 방식(사람이 작성한 계약서를 시스템에 올려 상태만 추적)
- **Invoice/Packing List/BOL**: Phase 3에서 자동 생성 여부를 별도 결정. 초기에는 업로드 방식으로 시작하고, 반복 패턴이 확인되면 자동 생성으로 전환하는 것을 권장합니다.
