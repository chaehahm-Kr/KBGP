---
문서: 05. 관리자 포털 / 외부 파트너 포털 메뉴 구조
---

두 포털은 **로그인 화면부터 분리**합니다. 같은 로그인 폼을 쓰더라도 로그인 이후 완전히 다른 메뉴·레이아웃·색상(관리자는 실무형 대시보드, 파트너는 마케팅 사이트와 톤을 맞춘 신뢰감 있는 화면)을 씁니다. 이는 `02_사용자유형과권한표.md`의 설계 원칙 3번(외부·내부 화면의 코드 수준 분리)과 연결됩니다.

`(P1)` `(P2)` `(P3)` 표시는 해당 메뉴가 등장하는 Phase입니다.

---

# A. 외부 파트너 포털 (회사 담당자용)

```
K Select Network — 파트너 포털
│
├─ 대시보드 (P1)
│    내 신청 현황 요약, 알림 목록, 다음 할 일(예: "제품 3개에 추가 자료 필요")
│
├─ 회사 정보 (P1)
│    ├─ 회사 프로필 (사업자 정보, 담당자 연락처, 생산 캐파, 인증 현황)
│    └─ 소속 사용자 관리 (Company Admin만 접근)
│
├─ 브랜드 & 제품 (P1)
│    ├─ 브랜드 목록 / 브랜드 등록
│    └─ 제품 목록 / 제품 등록 (이미지, 인증서 첨부 포함)
│
├─ 신청 관리 (P1)
│    ├─ 새 신청서 작성
│    ├─ 신청 현황 (상태별 목록: 제출됨 / 심사중 / 추가자료요청 / 승인 / 보류 / 반려)
│    └─ 신청서 상세 (포함된 제품별 개별 심사 상태 표시)
│
├─ 상담 & 메시지 (P2)
│    ├─ 미팅 예약
│    └─ Letusto와의 대화 (신청서별/제품별 스레드)
│
├─ 샘플 (P2)
│    └─ 샘플 요청 현황, 평가 결과 확인
│
├─ 견적 & 계약 (P2)
│    ├─ 받은 견적 목록 및 승인/협상
│    └─ 계약서 확인 및 서명 상태
│
├─ 발주(PO) (P2)
│    └─ PO 확인 및 승인/이의제기
│
├─ 주문 현황 (P3)
│    └─ 생산 → 검사 → 출고 → 배송 → 미국 입고까지 진행 상태 (읽기 전용)
│
├─ 문서함 (P3)
│    └─ Invoice, Packing List, BOL, 계약서 등 모아보기
│
└─ 계정 설정 (P1)
     프로필, 비밀번호, 알림 수신 설정, 언어(한/영)
```

# B. 관리자 포털 (Letusto 내부 직원용)

```
K Select Network — 관리자 콘솔
│
├─ 대시보드 (P1)
│    오늘 들어온 신청, 담당자별 처리 현황, 지연 건 경고(P3에서 고도화)
│
├─ 신청 관리 (P1)
│    ├─ 전체 신청 목록 (상태·담당자·회사명·제출일 필터)
│    ├─ 신청서 상세
│    │    ├─ 회사·브랜드·제품 정보 열람
│    │    ├─ 제품별 개별 심사 (승인/보류/반려 + 사유)
│    │    ├─ 신청서 전체 상태 변경
│    │    ├─ 추가 자료 요청 보내기
│    │    ├─ 내부 메모 (외부에 노출 안 됨)
│    │    └─ 담당자 배정/변경
│    └─ 심사 기준 관리 (참여 조건 항목을 관리자가 직접 수정 — 선택 기능, 없으면 코드 수정 필요)
│
├─ 회사 관리 (P1)
│    └─ 전체 회사 목록, 회사별 상세(등록된 브랜드·제품·신청 이력 통합 뷰)
│
├─ 상담 & 메시지 (P2)
│    ├─ 미팅 일정 관리
│    └─ 회사별 대화 스레드
│
├─ 샘플 관리 (P2)
│    └─ 요청 목록, 발송 처리, 평가 입력
│
├─ 견적 관리 (P2)
│    └─ 견적 작성, 발송, 협상 이력
│
├─ 계약 관리 (P2)
│    └─ 계약서 업로드, 상태 추적
│
├─ 발주(PO) 관리 (P2)
│    ├─ PO 작성/승인/발행
│    └─ 공급사 확인 현황
│
├─ 주문 이행 관리 (P3)
│    ├─ 생산·검사·출고·배송 상태 업데이트
│    ├─ 문서 관리 (Invoice, Packing List, BOL)
│    └─ 결제 상태 관리
│
├─ 리테일러 관리 (P3)
│    └─ 미국 매장 계정, 주문, 디스플레이 신청 처리
│
├─ 직원 관리 (P1, 단 기능은 최소)
│    └─ 직원 계정 생성/역할 부여 (Super Admin 전용)
│
├─ 활동 로그 (P1, 단 기능은 최소 → P3에서 고도화)
│    └─ 누가 언제 무엇을 변경했는지 이력
│
└─ 설정 (P1)
     이메일 템플릿, 알림 규칙, 다국어 문구 관리
```

# C. 설계 메모

- **관리자 포털의 "신청 관리"가 이 시스템의 심장부입니다.** Phase 1 개발에서 가장 먼저, 가장 정성 들여 만들어야 하는 화면입니다.
- **파트너 포털의 메뉴는 Phase가 올라갈수록 늘어나지만, 회사 입장에서는 하나의 연속된 이야기로 보여야 합니다.** "신청 → 상담 → 샘플 → 견적 → 계약 → PO → 주문현황"이 마치 택배 배송 조회처럼 하나의 타임라인으로도 볼 수 있게 하는 것을 Phase 2에서 검토하는 것을 권장합니다(신청서 상세 화면 안에 전체 타임라인 표시).
- 관리자 포털의 "심사 기준 관리"는 선택 기능으로 표시했습니다. 없으면 참여 조건 6가지가 코드에 고정되어, 조건을 바꿀 때마다 개발자가 코드를 수정해야 합니다. 있으면 관리자가 화면에서 직접 조건 문구를 수정할 수 있습니다. Phase 1에서는 코드에 고정하고, 실제 운영하면서 조건을 자주 바꾸게 되면 Phase 2에서 이 기능을 추가하는 것을 권장합니다.
